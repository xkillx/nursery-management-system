## Actionable findings (P1)

### PDF attachment ships placeholder/sample financial data
- **Severity:** P1 (product/quality, not a regression introduced by this plan)
- **Files:** `api/internal/modules/billing/infrastructure/pdf/layout.go:166-170`,
  `api/internal/modules/billing/infrastructure/pdf/renderer.go`
- **Description:** The gopdf renderer hardcodes sample values into every PDF:
  `RegNumber: "09876543"`, `BankName: "Barclays Bank UK"`, `SortCode: "20-45-89"`,
  `AccountNumber: "83920147"`, "Manager: Sarah Jenkins",
  "Registered in England and Wales: #12993844", "VAT Registration: GB 992 1122 33".
  These are now sent to parents as email attachments.
- **Fix (follow-up):** populate these from real site-profile data (add
  `InvoiceSiteProfile` fields + schema) or suppress the sections entirely when
  absent; never fall back to sample values.

### Fake line-item / dates can appear on the PDF
- **Severity:** P1 (only fires for empty/missing data; rare in practice)
- **Files:** `api/internal/modules/billing/infrastructure/pdf/renderer.go`
  (lines 417-427 fake "Full-Time Childcare … £900.00" row; lines 213-216 and
  176-179 fake due/issued dates; line 118-121 fake invoice number)
- **Fix (follow-up):** render a dash / nothing instead of placeholder content.

## Reliability findings (P2)

### S3 object deleted before outbox status is durable
- **Files:** `api/internal/modules/email/infrastructure/smtp/provider.go`,
  `api/internal/modules/email/application/send_pending.go`
- **Description:** The provider deletes the attachment inside `Send`, but the
  outbox status is written `sent` afterwards. If `UpdateStatus` fails after a
  successful SMTP send, the retry finds a missing object and dead-letters a
  delivered email.
- **Fix (follow-up):** delete the S3 object only after the `sent` status
  commits, or rely on an S3 lifecycle/TTL rule.

### PDF render + S3 upload happen inside the DB transaction
- **Files:** `api/internal/app/bootstrap/adapters.go` (`buildInvoiceAttachment`)
- **Description:** Rendering the PDF and uploading to S3 run inside the event
  handler's transaction, holding invoice row locks during render/network I/O; a
  rollback after a successful upload orphans the S3 object.
- **Fix (follow-up):** render/upload best-effort before opening the tx (or after
  commit), or add an S3 lifecycle/TTL cleanup.

## Minor (P3)

- In-flight v1 `receipt` messages still dead-letter (no `receipt_v1.*` exists);
  the missing receipt template is fixed only for v2 (the plan's R6).
- `Subject` interpolates `site.NurseryName` unescaped into a header
  (pre-existing CRLF-injection surface).
- `formatMoney` duplicated between `adapters.go` and `pdf/layout.go`; renders
  negatives as `£-10.50` (PDF renders `-£10.50`).
- `missing_content_v2.html` is a test fixture shipped inside the prod
  `//go:embed templates/*` (harmless, unreferenced).
- `version == 2` magic number in `renderer.go`; template payload is
  `map[string]interface{}` so a key typo renders `<no value>` silently.
